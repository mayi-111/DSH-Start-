# DSH 启动器

桌面快捷方式 **DSH**：双击后在右下角弹出状态小窗，自动拉起 DeepSeek Harness（`dsh web`）。

## 安装位置（重要）

- **只使用桌面快捷方式 `DSH`**（或 `Ctrl+Alt+D`）
- 快捷方式指向：`%LOCALAPPDATA%\DSH-Launcher\DSH.exe`（纯 ASCII 路径）
- 日志：`%LOCALAPPDATA%\DSH-Launcher\logs\dsh-launcher.log`
- 隔离配置目录（仅在需要时创建）：`%LOCALAPPDATA%\DSH-Launcher\dsh-home`
- 子进程 PID 记录：`%LOCALAPPDATA%\DSH-Launcher\dsh-child.pid`

> **为什么不要从本项目的 `dist\` 跑？**
> 本项目目录名是中文（`DSH启动器`）。早期曾以为"中文路径会让 exe 静默不执行"，但后来实测
> `dist\DSH.exe` **是能正常运行的**——真正的问题是它会成为**第二份可点开的程序**：
> 日志写到 `dist\logs\`，排查时两个日志文件对不上，也分不清自己点的是哪一份。
> 所以构建脚本在安装完成后会**自动删除 `dist\DSH.exe`／`DSH.ico`**（保留 `dist\logo.png`，
> 图标脚本和"标题图标"步骤要读它），确保系统里只有一个可运行副本。

## 使用

1. 双击桌面上的 **DSH** 图标（或按 `Ctrl+Alt+D`）。
2. 右下角出现小窗，依次显示：
   - **启动阶段**：`正在启动 DeepSeek Harness …` + 进度百分比（`12% → 40% → 72% → 88%`，就绪瞬间跳到 `100%`）
   - **运行阶段**：标题变为 `DSH 正在运行中`，进度条位置改为显示 **端口 · PID · 运行时间**（每秒刷新）
3. 小窗上的三个按钮：

| 按钮 | 启动中 | 运行中 | 已停止 / 失败 |
| --- | --- | --- | --- |
| 左（主按钮） | 打开页面（置灰，点击后记住：就绪即打开） | **打开页面**：默认浏览器打开 DSH Web | **启动服务** / **重试** |
| 中 | **停止服务**（先关掉 DSH 页面，再结束 `dsh web` 进程树） | **停止服务** | 置灰 |
| 右 | **关  闭**：只关掉这个右下角弹窗 | 同左 | 同左 |

- 首次启动成功会自动帮你打开一次 Web 页面；之后由「打开页面」按钮控制。
- **点「启动失败」了怎么办**：`dsh web` 启动时要写 `$DSH_HOME\profiles\web\cordis.yml`，
  这个写操作可能被**瞬时拒绝**（多个 DSH 抢同一个文件、安全软件拦截），表现为
  `EPERM: operation not permitted, open '...cordis.yml'`。启动器现在会自动重试：
  1. 原配置目录失败 → 等约 0.9 秒重试；
  2. 再失败 → 复制一份 profiles 到隔离目录 `%LOCALAPPDATA%\DSH-Launcher\dsh-home` 并用它重试；
  3. 仍失败 → 同样的错会**退避等待**（每次 +0.8 秒）再试，共 3 轮。
  3 轮都失败才报错；此时点「重试」会把重试链重置，可以再来 3 轮。
- 点「停止服务」= **只结束 `dsh web` 进程，不动浏览器**。
  浏览器里那个 DSH 页面保持原样，会显示「重新连接中…」；下次启动服务后刷新（或等它自己重连）即可继续用。
  实现上就是 `KillTree(pid)` 一步——原先"先找到浏览器窗口强行激活再发 `Ctrl+W`、失败退化为 `WM_CLOSE`"
  那套关标签页逻辑已**整体删除**（约 150 行，含 `FindWindowByTitleAndClass` / `SendCtrlW` / `ForceActivate`
  及 `EnumWindows`、`SendInput`、`INPUT`/`KEYBDINPUT` 等相关 P/Invoke）。
- 点「关闭」= 关掉弹窗 **并结束 DSH 服务**（避免后台留下孤儿进程）。若只想留服务、只关窗口，用窗口右上角的 `✕`。
- 小窗可以按住空白处拖动；缩略成圆球后也能**随意拖到屏幕任何位置**；`Esc` = 展开（缩略时）或关闭（展开时）。
- **不置顶、不抢游戏画面**：
  - 窗口是**普通层级**（`TopMost = false`），不会再浮在别的应用上方；正常情况下会被其他窗口盖住。
  - **全屏应用（游戏）在前台时，启动器自动隐藏**：每 1.5 秒检查一次前台窗口，只要它属于别的进程
    且矩形覆盖了整个显示器（>98%，连任务栏都盖住），就把启动器 `Hide()`。退出全屏后自动恢复。
    判定用的是"整块显示器"而不是工作区，所以被最大化的普通窗口**不会**被误判。
  - 恢复显示走 `ShowWithoutActivation`，**不会抢走你当前窗口的焦点**（你正在打字也不会被打断）。
  - 副作用：全屏游戏期间即使点桌面快捷方式，启动器也会在 1.5 秒内自动让路——想看面板请先退出/窗口化游戏。
- **缩略（待机小圆球）**：运行 **15 秒**后自动缩成**正圆**（直径 85px），点一下平滑展开回面板；
  展开后重新计时，15 秒后再次缩略。不在"运行中"状态（启动中/失败/已停止）时不会缩。
  - **圆外真透明**：缩略态把窗体背景色设为**透明色键**（`TransparencyKey`），并把"圆体 + logo"
    用 `e.Graphics` **直接画在窗体背景上**（抗锯齿 `FillEllipse` + 圆形裁剪画 logo）。
    圆边的抗锯齿混合像素会被系统映射成**半透明**，所以边缘平滑；圆外区域**真的透出桌面**、且点穿。
  - 关键：缩略态不再使用子控件（`LogoBox`）承载 logo——子控件是**不透明**绘制的，会把透明区画成实色。
  - 圆外区域点穿，点击只响应圆内（`InsideBubbleCircle` 命中判定），拖动/点击展开都在圆内生效。
  - **在原位收缩 / 在原位展开**：圆球固定在当前面板的右下角，不会跳回屏幕右下角；展开也以圆球当前位置为锚点。
  - 底部那行倒计时（`15s后缩小`、`14s后缩小` …）**可以点**：点一下不等倒计时，立即缩略；鼠标移上去会提亮。
- **大面板不使用 `TransparencyKey`**：透明色键会把文字抗锯齿的半透明边缘一起穿掉，在花哨壁纸上表现为字周围"重影/透底"；
  面板的圆角仍由窗体 `Region` 裁剪实现（只在缩略圆球上启用透明色键）。
- 面板尺寸 **480 × 200**；左侧 logo **62 × 62**；按钮为「打开界面 / 停止服务 / 关  闭」。
- 启动中在状态文字下方显示进度条；**就绪后进度条隐藏**，同一位置改为 `端口 · PID · 运行时间`，而且这行信息**常驻**：
  - 缩略成圆球、再展开回来，仍然是这行信息（不会被进度条顶掉）
  - 展开的瞬间就会填上内容，不等下一次刷新
  - 实现要点：`SetPanelContentVisible(true)` 会把所有控件设成可见，所以展开后必须调用
    `ApplyContentVisibility()` 按状态归一化（进度条只在"启动中"显示，运行信息只在"运行中"显示）。

## 行为细节

- 窗口是**圆角无边框**的：窗体按 14px 圆角裁剪（`Region`），四角落在圆角之外，不依赖透明色键（见上）。
- 布局：第一行是标题 **DeepSeek Harness**（下面有一条分隔线，与内容区分）；第二行往左是
  **logo（24px）**，右边是状态文字，再下面是进度条。主窗体标题（任务栏悬停提示）也是 `DeepSeek Harness`。
- logo 由程序目录下的 `logo.png` 加载；桌面快捷方式的图标是同一个图源生成的多尺寸 `DSH.ico`。
  - 图源：项目根目录下的 logo 图片（`logo.png` / `LOGO.png` / `tp.png` 等，按此顺序取第一个）。
  - `make-icon.ps1` 会**居中裁成正方形 → 缩放 → 圆角透明**，再输出 `dist\DSH.ico`（16/32/48/64/128/256）与 `dist\logo.png`（256px，供标题行用）。
  - 换图标：换掉项目根目录的图片，运行 `build.ps1` 即可（脚本会重新生成图标、编译、安装、重建快捷方式）。
  - 注意：logo 文件若是**隐藏属性**，PowerShell 的 `Test-Path`/`Copy-Item` 会当成不存在；脚本内部统一用 `[System.IO.File]` 处理，不受影响。
- 运行中那一行 `端口 · PID · 运行时间` **每秒刷新**：
  - 自启动的实例显示启动器拉起的子进程 PID；
  - 接管的实例通过 `netstat` 反查真实 PID，并用该进程的真实启动时间计算运行时间（不是从接管时刻算起）。
  - 实现要点：**绝不能在 WinForms Timer 的 Tick 回调里 `Stop()` 之后再 `Start()`**（.NET Framework 下不会再生效，界面会永久停止刷新）；所有 `Stop()` 都做了 `_inTick` 保护。
- 默认使用端口 **3080**（与 `dsh web` 的默认值一致）。
- 如果 3080 **已经在跑 DSH**（比如你已从命令行启动过），启动器不会重复拉起，而是直接接管显示，明细行标注「已在运行的实例（非本启动器管理）」。探测会重试一次，避免对方还在启动中时误判。
- 如果 3080 被**别的程序**占用，启动器会改为让系统自动分配端口，不会抢端口。
- 子进程以 `node <dsh>/lib/bin.js web --no-open --port <n>` 启动，工作目录为当前用户主目录；
  就绪信号取自 `dsh web: http://127.0.0.1:<port>/?token=…` 这一行（含启动令牌，保证打开的页面直接通过浏览器信任校验）。
- 启动超时 4 分钟；失败时小窗显示错误原因（例如 `EADDRINUSE`、`EPERM`），主按钮变成「重试」。
- 日志写在 `%LOCALAPPDATA%\DSH-Launcher\logs\dsh-launcher.log`（含子进程 stdout/stderr），排查问题看这个文件。

### 三种“起不来”的情况怎么处理

1. **端口 3080 上已经有 DSH 在跑**（你从别处启动过、或上一次没关干净）
   启动器会先请求 `http://127.0.0.1:3080/` 判断：只要能收到 HTTP 响应就认定是 DSH，
   **直接接管显示**，不会再拉第二个进程去抢同一个配置文件。
   明细行会写「已在运行的实例（非本启动器管理）」。

2. **配置目录被占用 / 被同步软件锁住**
   症状是日志里出现
   `EPERM: operation not permitted` 或 `EBUSY: resource busy or locked, open 'C:\Users\MSI\.dsh\profiles\web\cordis.yml'`。
   这通常是因为已有一个 DSH 实例占着这个文件（百度网盘 / WPS 云盘同步该目录也会造成）。
   启动器检测到这个特征后，会**自动用隔离的配置目录重试一次**
   （`%LOCALAPPDATA%\DSH-Launcher\dsh-home`，只复制 `profiles`，不复制凭据），成功则正常进入「正在运行中」。
   隔离重试只做一次；仍失败会直接显示错误，不会反复重启。

3. **一直停在很小的百分比不动（例如 3%）**
   说明启动器在等子进程打印就绪行。日志里每 5 秒有一条心跳：

   - `waiting: pid=… alive=True port=3080 portAlive=… progress=…` → 子进程还活着但没就绪，
     看同一文件里 `[out]` / `[err]` 的子进程输出，一般是端口被占或配置目录被锁。
   - 只有 `spawned pid=…` 之后什么都没有 → 子进程秒退，错误会显示在弹窗明细行上。
   - 无论哪种，超过 4 分钟都会转成「启动失败 + 重试」，不会永远卡住。

   把 `%LOCALAPPDATA%\DSH-Launcher\logs\dsh-launcher.log` 发出来即可精确定位。

## 文件结构

```
DSH启动器\                     （项目/源码目录，中文名，不直接运行里面的 exe）
  dist\DSH.exe                 编译产物（构建后会被安装到 %LOCALAPPDATA%）
  dist\DSH.ico                 图标
  src\DSH.cs                   全部源码（单文件 WinForms）
  build.ps1                    编译 + 安装到 %LOCALAPPDATA%\DSH-Launcher + 重建快捷方式
  make-icon.ps1                重新生成图标
  tools\                       自检辅助脚本（截图 / 窗口探针 / 文件锁 / 反射调用）
%LOCALAPPDATA%\DSH-Launcher\   实际运行位置（纯 ASCII 路径）
  DSH.exe  DSH.ico  logs\  dsh-home\
```

## 重新编译

**最简单：双击项目目录里的 `构建.bat`**（会自己切到项目目录、绕过执行策略限制、跑完停住等你看结果）。

等价的手动方式：

```powershell
# 在项目目录里开 PowerShell，然后：
powershell -ExecutionPolicy Bypass -File build.ps1              # 编译 + 安装 + 重建快捷方式
powershell -ExecutionPolicy Bypass -File build.ps1 -NoShortcut # 只编译
powershell -ExecutionPolicy Bypass -File build.ps1 -NoIcon     # 不重新生成图标，只编译
```

或者文件资源管理器里：右键 `build.ps1` → **使用 PowerShell 运行**（若报执行策略错误，就用上面的 `构建.bat`）。

它会依次：① 用项目根目录的图片重生成图标 → ② 编译 `DSH.exe` → ③ 安装到 `%LOCALAPPDATA%\DSH-Launcher` → ④ 重建桌面快捷方式。
**注意**：跑之前先关掉正在运行的启动器（否则 `DSH.exe` 被占用，会提示 `cannot replace ... close the running launcher`）。

依赖：Windows 自带的 .NET Framework 4.x 编译器（`csc.exe`）与 Node.js，无需安装任何第三方组件。

## 命令行参数（一般用不到）

| 参数 | 作用 |
| --- | --- |
| `--port <n>` | 强制使用指定端口（`0` = 让系统分配） |
| `--no-auto-open` | 就绪后不自动打开浏览器 |
| `--no-bubble` | 关闭"15 秒后缩成小圆球" |
| `--collapse-after <秒>` | 自检用：覆盖缩略前等待的秒数（默认 15） |
| `--pos <x> <y>` | 指定面板初始位置（默认屏幕右下角） |
| `--autoclose <秒>` | N 秒后自动退出（自检用） |
| `--log <路径>` | 把启动器日志写到指定文件 |
| `--headless` | 窗口完全透明（自检用） |
